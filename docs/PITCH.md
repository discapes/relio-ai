## Walkthrough

### 0:00–0:40 — Start with the employee's work

Open **My workspace** and the morning brief.

“Ana manages the Acme rollout. Relio prepares the project changes, decisions and follow-ups she needs for customer conversations. Her own goals influence what appears here. Each item has dated evidence.”

Open a receipt and inspect the original passage. Point out archive coverage and the simulated July project date. Return to the workspace.

### 0:40–1:35 — Show how shared memory grows

Open **Email demo**, load the bakery scheduling example and show the employee's address and agent's visible Cc entry. Send it.

“This represents Ana's Outlook. She includes the project memory address in the conversation. That delivered message becomes shared knowledge at its audience level. Her private conversation with the assistant stays in her personal workspace.”

Show delivery status. This update normally merits silent receipt. While it processes, show the saved personal preference and explain the difference between mailbox membership and shared project access.

### 1:35–2:15 — Recover the new information

Ask in **My workspace**:

> When is the bakery evidence review, and what did I say I would prepare?

Inspect the new message citation. The example schedules Thursday 9 July at 10:00 Helsinki time and assigns Ana the comparison of prepared extracts and a separate environment. Show its calendar entry or refreshed preparation when ready. Historical estimates must retain their original dates and scope.

### 2:15–3:30 — Let the agent find the important mistake

Load and send the sign-off example. It asserts that January 2025 approval covered the whole programme, including fresh categories.

“There is a consequential mistake in this message. The agent decides whether it has something useful to contribute, using the project's permitted evidence.”

During generation, open the historical sign-off sources in Project memory: Ana's 21 January wording and Lena's 22 January confirmation. Return to the thread and inspect the completed reply. Its supported correction is the 25-store pilot covering ambient and dry goods, with fresh and overall programme acceptance excluded. The signed attachment itself is unavailable.

### 3:30–4:10 — Explain the boundary and evidence

Open a supporting source, briefly show its claim in Project memory and show a prepared customer evidence card if available. Otherwise start card generation and display its progress.

“The application selects the evidence before calling the model. A customer answer is generated from L1 material. The card retains its evidence and dates.”

Show copy or PNG export. Downloaded copies have a separate retention boundary.

### 4:10–5:00 — Erase a person and retain independent evidence

Open **People**, select Kwame Boateng and confirm erasure in the presenter workspace. Inspect the receipt. Ask:

> What was the agreed scope of the January 2025 UAT sign-off, and who confirmed it?

“The application has removed the person's evidence and invalidated derived answers. Ana and Lena independently establish the approval scope. The next answer uses surviving sources.”

Open surviving Ana/Lena evidence while generation runs. Show the completed response if ready. If generation extends past the pitch slot, state its status; judges can inspect the same workspace afterward.

## Questions to prepare

| Question                                                 | Answer and evidence to show                                                                                                                                                                        |
| -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| What runs autonomously?                                  | Brief refresh and email participation. Show a completed job and an unrequested, sourced reply; routine mail can receive silence.                                                                   |
| Is Outlook connected?                                    | Mailbox and transport are simulated. Sending invokes actual ingestion, audience selection and inference inside the application. A production mailbox integration would feed the delivery boundary. |
| Does Cc establish consent?                               | It makes participation visible and expresses the collection convention. Legal consent requires separate policy decisions.                                                                          |
| How are facts checked?                                   | The server binds source IDs and exact passages; a verification pass checks draft claims. Open a source and distinguish source binding from semantic correctness.                                   |
| What happens when evidence changes?                      | Delivered sources trigger refreshed claims and briefs. Generation considers corrections and agreement scope. Original runtime evidence remains inspectable.                                        |
| Why does project memory contain mail Ana never received? | Mailbox membership is message-specific; project membership also grants access to shared evidence from other permitted conversations.                                                               |
| What personalises the brief?                             | Role, saved private goals, recent private conversation and simulated meetings. Show a preference and another employee's isolated state.                                                            |
| How is customer output scoped?                           | Sharing generates a fresh L1 answer. Show the level selector and a source-access check.                                                                                                            |
| What is erased?                                          | Runtime personal evidence, identifying metadata and affected private/mail state. Claims and answers are invalidated; the epoch rejects earlier in-flight results.                                  |
| What remains outside erasure?                            | Protected fixtures, independent workspaces, downloaded copies and infrastructure-managed caches/backups. Reset creates a separate workspace.                                                       |
| Where does inference run?                                | GLM 5.3 Flash on Verda (formerly DataCrunch) in Helsinki, reached through the localhost SSH tunnel.                                                                                                            |
| What production work remains?                            | Identity/mail/calendar integrations, organisation-owned classification, broader semantic/alias evaluation, infrastructure retention controls and measured load behaviour.                          |
